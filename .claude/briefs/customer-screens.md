# Phase 2 builder brief (shared by every customer-screen builder)

Project: the project root. Read first: `CLAUDE.md`, `.claude/agents/screen-builder.md`, `docs/design-system.md` (whole), and the Customer section of `docs/plan.md`. Brief extracts that matter most are below; the full brief is `docs/brief.md` (read the "Design standard" section).

## What already exists (use it, do not re-create or edit it)
- Layout: `resources/js/layouts/public-layout.tsx` is applied automatically to every page outside `auth/`, `settings/`, `styleguide/`. It has the desktop top nav, mobile top bar + bottom tab bar (64px + safe area), footer, skip link (`#main`), offline banner. Do not add another header.
- Shared props on every page (`usePage().props`): `name`, `restaurant` {name, phone, email, address{line1,city,postcode}, company}, `translations`, `auth.user` (nullable, has `role`), `basketCount`, `openStatus` {isOpen, until, opensAt}, `footer`. Types in `resources/js/types/*.ts` (`MenuItem`, `Category`, `Variant`, `ModifierGroup`, ...).
- Translations: `const t = useT()` from `@/lib/i18n`; `t('group.key', { name: 'x' })` resolves `lang/en_GB/<group>.php` with `:name` placeholders. Create your own group file (named in your task). Existing groups: ui, nav, cart, allergens, stations, roles. Never hard-code user-facing English in TSX.
- Money: `formatMoney(pence, { compact })` from `@/lib/money`; `<Price pence>` component.
- Brand components (`resources/js/components/brand/`): `ArchFrame`, `Picture` (mediaKey like `dish/<slug>` or `story/tandoor|hands|naan|room|table|spices|chai|pass`, `hero/poster`), `HeroVideo`, `EmberLine`, `SectionHeading`, `Logo/LogoMark`, `AllergenIcon` + `allergenCodes`, `AllergenList`, `DietMarks`, `SpiceMeter`, `Price`, `QuantityStepper`, `OpenStatus`, `EmptyState`, `ErrorState`, `OfflineBanner`/`useOnline`, `TicketSteps`, `ThemeToggle`, `StickyActionBar`.
- Menu components: `components/menu/dish-row.tsx` (`DishRow`, `DishRowSkeleton`), `dish-card.tsx` (`DishCard` with `layoutId={'dish-photo-'+slug}`, `DishCardSkeleton`).
- Motion (`components/motion/served.tsx`): `Plate`, `Course`, `Serve`, `Settle`, `PhotoPrint`, `DoorReveal`, `MarkerDrop`, `Stamp`, `CountUp`, `SteamWisp`. Tokens in `@/lib/motion` (`spring`, `uiTransition`, `duration`, `ease`). Public pages are the most expressive; ordering/checkout stay under 250ms and functional.
- UI primitives (`components/ui/`): button (variants default/outline/secondary/ghost/destructive/link; sizes sm/default/lg/icon), input, textarea, select, checkbox, radio-group, switch, tabs, dialog, sheet, popover, badge (default/secondary/destructive/outline/leaf/turmeric/solid), skeleton, label, tooltip; toasts via `toast` from `sonner`. Server flash toasts: `Inertia::flash('toast', ['type' => 'success', 'message' => ...])`.
- Basket: `App\Services\CartService` (inject it): `add()`, `update()`, `remove()`, `clear()`, `useChannel(OrderChannel, ?DiningTable)`, `applyPromo()`, `count()`, `summary(?deliveryFee, tip)` returns lines (key, slug, name, variant, modifiers[{name,price}], notes, quantity, unit_price, total, allergens, image, is_available, is_alcoholic) + totals (subtotal, discount, delivery_fee, service_charge, tip, vat_total, total, count, channel, promo_code, promo_invalid, has_unavailable, has_alcohol). Routes `POST /basket/lines`, `PATCH /basket/lines/{key}` {quantity}, `DELETE /basket/lines/{key}` exist (CartLineController). Front end: `useAddToBasket()` from `@/lib/basket` → `add(payload, originElement)` (animates a plate to the basket).
- `App\Services\Pricing` (totals, VAT-inclusive), `App\Services\OpeningHours` (status(), periodsOn(), week(), isOpen()), `App\Support\Settings` (get('opening_hours'|'service_charge_rate'|'reservation.*'|'tip_presets'|'pickup_slot_minutes'|'pickup_lead_minutes'|...), see `config/restaurant.php` defaults).
- `App\Http\Resources\MenuItemResource` (snake_case keys; eager-load `variants`, `modifierGroups.modifiers` when you need them). `JsonResource::withoutWrapping()` is on. Models are strict: eager-load everything (lazy loading throws).
- Routes are ALREADY defined in `routes/web.php` — do not edit it. Create the controllers it names for your task, under the exact class names and method names it uses.
- Demo data: `php artisan migrate:fresh --seed` (orders, reservations, reviews, tables, zones, addresses, promo codes WELCOME10 / TANDOOR5). Demo logins (password `password`): customer@tandoorhouse.test etc.
- Local server for checking: http://127.0.0.1:8010 from `php artisan serve --port=8010` (the main session starts it; if it is down, start one on a free port 8020–8029 and pass BASE_URL to the screenshot script). After front-end changes run `npm run build` before checking in a browser. Screenshot check: `node scripts/screenshots.mjs 2 <name>=<path>` writes to docs/screenshots/phase-2 (full-page jpgs); view them only at reduced size — make a contact sheet with `node scripts/contact-sheet.mjs <in.jpg> storage/app/review/<name>.jpg 2400` and look at the 375 light version; spot-check 1280 and dark.

## Rules that reviewers will check
- Mobile first: 375 → 768 → 1280. 44px touch targets. Primary action thumb-reachable on mobile (`StickyActionBar`). Keyboard and screen reader usable; landmarks, labels, `aria-live` for changing totals.
- Every screen has: loading (skeleton shaped like the content — use Inertia deferred props `Inertia::defer()` + `<Deferred>` or the skeleton components where data loads late), empty, error (form errors inline, `ErrorState` for failures), offline (layout banner covers it; disable submit when `useOnline()` is false), success, disabled states.
- Tokens only (no hex, no arbitrary colours). No purple/blue gradients, no glassmorphism, no emoji as icons (lucide icons are fine), no hero + three identical cards, no identical card grids everywhere, no stock copy ("Welcome to our restaurant", "delicious"). Copy is short, warm, specific, British English.
- Allergens are always visible as text, never only behind a tap.
- Laravel: Form Request classes for validation, policies or explicit authorisation where a resource belongs to a user (e.g. an order belongs to the signed-in user or to the guest's session), eager loading, typed Inertia props (define TS prop types per page). Money in pence.
- Pest feature tests for your controllers (happy path, validation errors, authorisation for other users / guests). Use `Database\Seeders\MenuSeeder` and factories in tests; the DB uses RefreshDatabase (see tests/Pest.php).
- Before finishing: `npm run types:check`, `npx vp check --fix` (formats your files; fine), `vendor/bin/pint --parallel`, `php artisan test --compact`, `vendor/bin/phpstan analyse --memory-limit=1G` — fix everything in your files; report (do not fix) problems in files you do not own.
- Do not commit. Do not edit files outside your list. If you need a change in a shared file, describe it in your summary.
- Return a summary under 150 words: files, what each screen covers, anything missing, any shared-file change you need.
